# 4.0 自有化与闭源路线

4.0.0 完成的是「独立仓库 + 自有品牌」：新 git 历史、自有版本线、清掉 APM 远程业务。**代码仍然来自 AYA**，所以许可证仍是 AGPL-3.0。本文档列出要走到闭源发布还缺什么，按优先级排列。

## 合规红线

- 仓库里还有 AYA 代码 → 对外分发（客户现场安装、发给集成商）必须提供对应源码，且保持 AGPL-3.0。
- 仅内部自用（不对外分发二进制、不对外提供网络服务）时没有分发义务。
- 把 `license` 字段改成别的、或把仓库设为私有，都不改变上面的结论；只有「代码不再是衍生作品」才成立。

## 待替换清单（按依赖顺序）

| 阶段 | 范围 | 规模 | 说明 |
| --- | --- | --- | --- |
| P0 ✅ | 品牌与仓库 | — | 已完成：新仓库、新历史、作者/描述/关于页/菜单文案、移除子模块与捐赠入口 |
| P1 | 渲染层 UI 组件 | ~7.0k 行 + `luna-*` 依赖 | 把 `luna-toolbar`/`luna-file-list`/`luna-data-grid`/`luna-setting` 等 22 个 MIT 组件替换为自研组件；MIT 许可本身允许闭源，但要做到「零 AYA 生态」就得换 |
| P2 | `src/share` 窗口骨架 | ~2.8k 行 | 上游 electron-share 的内联副本（终端、进程、关于、设置、预览等通用窗口），需重写成自己的窗口框架 |
| P3 | `src/main` | ~5.7k 行 | adb 封装、投屏内核、菜单。功能大多是自己写的，但文件结构与工具函数沿用 AYA，需要逐文件重写并保留行为 |
| P4 | `server/` + `resources/aya.dex` | Java ~1k 行 | Java 包名 `io.liriliri.aya`、抽象 socket `aya`、`/data/local/tmp/aya`、protobuf `io.liriliri.aya.*` 协议都要改成自有命名，并用 Android SDK 重新编译 dex；改完 TS 侧 `server.ts`/`wire.*` 同步 |
| P5 | 全库清扫 | — | 清掉 `AYA`/`liriliri` 残留字样、更新 LICENSE/NOTICE、换自有图标与安装器素材，再切闭源许可 |

## 建议的实施方式

1. **P1 先做「投屏 + 设备页」**：这两块用户感知最强、组件依赖最少，替换后可以先验证视觉与交互不回退。
2. **每个阶段独立可发布**：替换一层就出一个 2.x 版本，保持 AGPL 开源；不要在中间状态切闭源。
3. **回归基线**：每阶段跑 `npm run typecheck && npm test && npm run lint && npm run smoke`，再出 dmg 做实机冒烟（投屏、文件搜索、应用列表）。
4. **P4 单独排期**：需要 Android SDK / gradle 环境，dex 重建后必须用真机验证应用名/图标/搜索三条链路。

## 当前 4.0.0 的已知「非自有」痕迹

- `resources/aya.dex`、`server/` 里的 `io.liriliri.aya` 包名、`localabstract:aya` socket、`/data/local/tmp/aya` 目录
- 内部代码里的 `AyaClient`、`aya_separator`、`__aya_exit` 等标识符与协议字符串
- `wire.d.ts`/`wire.js` 由上游 proto 生成，命名空间为 `io.liriliri.aya`

这些不影响 4.0.0 使用，但在闭源前必须清掉（P4/P5）。
