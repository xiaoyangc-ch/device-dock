## 仍然建议保留 AGPL 的理由

1. **`*.module.scss` 未重写**：布局结构与上游接近。视觉设计属于表达性内容，是否构成衍生作品有争议。
2. **`src/renderer/webcast/App.tsx` 未重写**：投屏窗口（WebCodecs 解码 + 输入注入 + 剪贴板 + 录制）。无上游代码标识，但结构与上游同源，未逐行核对。
3. **产品形态与交互流程**与上游相似（侧栏导航 + 各功能页）。这属于「思想」而非「表达」，一般不构成衍生，但不宜由我们自己下结论。

结论：**可以按自有实现对外描述，但不建议据此切换闭源许可**。若要闭源，建议先就上面两点做法务复核。

## 如果继续收敛

1. 逐个重写 `*.module.scss`：按现有视觉效果重新组织类名与层级，约 2–3 天（纯手工，无逻辑风险）。
2. 重写 `webcast/App.tsx`：保持 `@yume-chan/scrcpy` 的 API 调用不变，重组状态机与输入映射，约 1–2 天，需真机回归投屏/输入/录制。
3. `src/renderer/icon.css` 由 Lucide 生成（ISC，可闭源），无需处理。
