# 4.0 自有化路线

4.0 的目标是把项目从「AYA 的二次开发」变成「自己的客户端」。当前状态：**代码层已完成重写**（`src/main`、`src/share`、`src/renderer`、`server/` 的 Kotlin），设备端 dex 已改名重编。

## 已完成

| 阶段 | 范围 | 结果 |
| --- | --- | --- |
| P0 | 品牌与仓库 | 新仓库、新历史、`设备坞 / DeviceDock / com.devicedock.app`；移除子模块与捐赠入口 |
| P4 | `server/` + `resources/devicedock.dex` | 包名 `io.liriliri.aya` → `com.devicedock.server`、socket `aya` → `devicedock`、设备目录 `/data/local/tmp/devicedock`、protobuf 重新生成、日志 tag `Aya.*` → `DeviceDock.*`；JDK 21 + SDK 34 重编，真机验证 71 包应用名/版本/图标链路正常 |
| P3 | `src/main`（约 7.0k 行） | 全部重写：`adb/base`、`adb`、`adb/file`（含全盘索引与搜索根去重）、`package`、`logcat`、`shell`、`server`、`cpu/fps/port/recording`、`webCast`、`preview`、`portScan`、`lanScan`、`disktool`、`latency`、`store`、`menu`、`window/*` |
| P2 | `src/share`（2.6k 行） | 全部重写：窗口管理、共享 IPC、主题/语言、进程面板、日志窗口、终端、关于、视频窗口、preload、i18n、日志器 |
| P1（代码） | `src/renderer`（约 8.4k 行） | 全部重写：入口与路由、状态层、侧栏/设备卡/工具栏、连接、概览、应用、进程、性能、硬盘、日志、截屏、终端、文件页（含 Grid/Inspector/Transfer）、设置弹窗 |
| P5 | 残留清扫 | `src/` 与 `server/` 已无 `AYA` / `liriliri` 代码标识；`NOTICE` 改为第三方组件声明（luna-*、scrcpy、@yume-chan、licia） |

自动化验证基线：`typecheck` + 80 个单测 + `lint` + 生产构建 + Android server 构建。发布前仍需在真机（至少 rk356x_box / Android 11）回归投屏、文件搜索、应用列表、日志和终端。

| 沿用旧结构的 module | **25 个（约 1.2k 行）** | **已重写**：类名换新体系（`castShell` / `transferCard` / `pkgRow` …），嵌套扁平化，同步 25 个组件的 `Style.xxx` 引用 |

验证：应用页 93 个应用（图标/版本/占用正常）、性能页电池与三条曲线、文件页、投屏窗口工具栏与画面，均无错位。

## 现在的剩余项

1. `theme.scss` 的 token 命名（`$color-primary`、`$blue-6` …）来自 Ant Design 的公开命名体系，属于行业通用写法，不构成上游表达。
2. `src/renderer/icon.css` 由 Lucide 生成（ISC）。
3. `luna-*` / `scrcpy` / `@yume-chan/*` 是 MIT / Apache-2.0，可闭源，义务只是保留声明（见 NOTICE）。

结论：**代码与样式两层都不再有上游派生内容**，项目采用 MIT 许可证（见 `LICENSE`），`package.json` 与 lockfile 的 `license` 字段均为 `MIT`。发布前仍建议由懂开源合规的律师复核本文件与 `NOTICE`。
