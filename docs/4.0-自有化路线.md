# 4.0 自有化与闭源路线

4.0.0 完成的是「独立仓库 + 自有品牌 + 设备端去 AYA」：新 git 历史、自有版本线、清掉 APM 远程业务，设备端 `devicedock.dex` 已替换 `aya.dex`（包名 `com.devicedock.server`、socket `devicedock`、协议重新生成）。**`src/` 的 TypeScript 仍是 AYA 派生代码**，所以许可证仍是 AGPL-3.0。本文档列出要走到闭源发布还缺什么，按优先级排列。

## 合规红线

- 仓库里还有 AYA 代码 → 对外分发（客户现场安装、发给集成商）必须提供对应源码，且保持 AGPL-3.0。
- 仅内部自用（不对外分发二进制、不对外提供网络服务）时没有分发义务。
- 把 `license` 字段改成别的、或把仓库设为私有，都不改变上面的结论；只有「代码不再是衍生作品」才成立。

## 建议的实施方式

1. **P3 先做 `src/main`**：它决定内核是不是自己的，替换后 `src/renderer` 的页面可以逐步跟上。
2. **每个阶段独立可发布**：替换一层就出一个 4.x 版本，保持 AGPL 开源；不要在中间状态切闭源。
3. **回归基线**：每阶段跑 `npm run typecheck && npm test && npm run lint && npm run smoke`，再出 dmg 做实机冒烟（投屏、文件搜索、应用列表）。
4. **P4 已完成的验证点**：设备端 `/data/local/tmp/devicedock/devicedock.dex`、socket `@devicedock`、应用页 71 个应用的名称/图标正常。

## 当前 4.0.0 的「非自有」范围

- `src/main`、`src/share`、`src/renderer` 的 TypeScript 实现仍沿用 AYA 的文件结构与工具函数（这是 AGPL 义务的来源）
- `src/renderer/icon.css` 由 Lucide 生成（ISC，可闭源）
- `luna-*` / `@yume-chan/scrcpy` 等第三方库是 MIT/Apache-2.0，可继续使用
- `NOTICE` / `LICENSE` / 关于页里的 AYA 版权声明是 AGPL 要求，**P1–P3 完成前不能删**
